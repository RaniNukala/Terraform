# 🗺️ AWS Management Console - Individual Resource GUI Blueprint Guide

This comprehensive reference document outlines the step-by-step graphical user interface (GUI) interactions required to construct an enterprise network topology within the **AWS Free Tier** limits.

| AWS Resource Component | Detailed Individual Step-by-Step GUI Management Instructions |
| :--- | :--- |
| **1. Virtual Private Cloud (VPC)** | 1. Navigate to the **AWS VPC Console** and select **Your VPCs** on the left menu.<br>2. Click **Create VPC**.<br>3. Under *VPC settings*, check **VPC only**.<br>4. Configure parameters: **Name tag:** `prod-vpc` \| **IPv4 CIDR block:** Manual entry of `10.10.0.0/16`.<br>5. Click **Create VPC** at the bottom of the screen. |
| **2. Subnets (Public & Private)** | 1. In the VPC Console, select **Subnets** -> click **Create subnet** -> choose `prod-vpc` from the dropdown.<br>2. **Subnet 1 (Public):** Name: `prod-public-subnet` \| AZ: `us-east-1a` \| IPv4 CIDR: `10.10.1.0/24`.<br>3. Click **Add new subnet**.<br>4. **Subnet 2 (Private):** Name: `prod-private-subnet` \| AZ: `us-east-1a` \| IPv4 CIDR: `10.10.2.0/24`.<br>5. Click **Create subnet**.<br>6. **Enable Public IPs:** Highlight `prod-public-subnet` -> click **Actions** -> **Edit subnet settings** -> check **Enable auto-assign public IPv4 address** -> click **Save**. |
| **3. Internet Gateway (IGW)** | 1. In the VPC Console, click **Internet gateways** on the left sidebar -> click **Create internet gateway**.<br>2. Set **Name tag:** `prod-igw` -> click **Create internet gateway**.<br>3. On the confirmation screen, click the **Actions** menu at the top right -> choose **Attach to VPC**.<br>4. Select `prod-vpc` from the dynamic interface list -> click **Attach internet gateway**. |
| **4. Route Tables** | **[Public Route Infrastructure Link]:**<br>1. In the VPC Console, click **Route tables** -> select the default route table associated with your `prod-vpc`. Name it `prod-public-rt`.<br>2. Select the **Routes** tab at the bottom panel -> click **Edit routes** -> click **Add route**.<br>3. Configure path: Set *Destination* to `0.0.0.0/0` \| Set *Target* to **Internet Gateway** and select your `prod-igw` -> click **Save changes**.<br>4. Select the **Subnet associations** tab -> click **Edit subnet associations** -> check the box for `prod-public-subnet` -> click **Save associations**.<br><br>**[Private Route Infrastructure Link]:**<br>1. Click **Create route table** -> Set **Name:** `prod-private-rt` \| **VPC:** Select `prod-vpc` -> click **Create**.<br>2. Select the **Subnet associations** tab -> click **Edit subnet associations** -> check the box for `prod-private-subnet` -> click **Save associations**. |
| **5. Key Pair** | 1. Access the **AWS EC2 Console** layout page.<br>2. On the left menu under *Network & Security*, click **Key Pairs**.<br>3. Click **Create key pair**.<br>4. Configure properties: **Name:** `enterprise-free-keypair` \| **Key pair type:** `RSA` \| **Private key file format:** Select `.pem`.<br>5. Click **Create key pair** to initiate an automatic browser file download. Save the file securely to your desktop. |
| **6. Security Groups** | **[Bastion Jump Box Security Group]:**<br>1. In the EC2 Console left menu under *Network & Security*, click **Security Groups** -> click **Create security group**.<br>2. Set **Security group name:** `bastion-security-group` \| **Description:** `Allow SSH from anywhere` \| **VPC:** Clear text and select `prod-vpc`.<br>3. Under *Inbound rules*, click **Add rule** -> Set *Type:* `SSH` \| Set *Source:* `Anywhere-IPv4` (`0.0.0.0/0`).<br>4. Click **Create security group**.<br><br>**[Private App Node Security Group]:**<br>1. Click **Create security group** again.<br>2. Set **Security group name:** `private-app-security-group` \| **Description:** `Allow internal access from bastion` \| **VPC:** Select `prod-vpc`.<br>3. Under *Inbound rules*, click **Add rule** -> Set *Type:* `SSH` \| Set *Source:* Click the field, clear text, and select the security group named **`bastion-security-group`** from the contextual menu layout.<br>4. Click **Create security group**. |
| **7. EC2 Instances** | **[Public Bastion Host Deployment]:**<br>1. In the EC2 Console, select **Instances** on the left menu -> click **Launch instances**.<br>2. **Name:** `bastion-host` \| **OS Image:** Select **Ubuntu** (verify the *Free Tier Eligible* label exists underneath).<br>3. **Instance type:** Select `t2.micro` \| **Key pair:** Choose `enterprise-free-keypair`.<br>4. **Network settings:** Click **Edit** -> **VPC:** `prod-vpc` \| **Subnet:** `prod-public-subnet`. Under *Firewall*, select **Select existing security group** and check the box for `bastion-security-group`.<br>5. Click **Launch instance**.<br><br>**[Isolated Private App Server Deployment]:**<br>1. Return to **Instances** -> click **Launch instances** again.<br>2. **Name:** `isolated-app-server` \| **OS & Type:** Select **Ubuntu** and `t2.micro`.<br>3. **Key pair:** Choose `enterprise-free-keypair`.<br>4. **Network settings:** Click **Edit** -> **VPC:** `prod-vpc` \| **Subnet:** `prod-private-subnet`. Under *Firewall*, select **Select existing security group** and check the box for `private-app-security-group`.<br>5. Click **Launch instance**. |
| **8. Elastic Block Store (EBS)** | 1. In the EC2 Console left menu under *Elastic Block Store*, click **Volumes** -> click **Create volume**.<br>2. Configure settings: **Volume type:** `gp3` \| **Size:** `10` GiB \| **Availability Zone:** Select **`us-east-1a`** *(Must match instance zone)*.<br>3. Click **Create volume** -> locate your new volume in the list (shows in an `available` status) and check its row box.<br>4. Click the **Actions** button at the top right -> select **Attach volume**.<br>5. **Instance:** Select `isolated-app-server` from the search field dropdown -> leave device target as `/dev/sdh` -> click **Attach volume**. |
| **9. VPC Peering Connections** | 1. In the VPC Console, click **Peering connections** on the left menu sidebar -> click **Create peering connection**.<br>2. Set **Name:** `prod-to-corp-peering` \| **VPC ID (Requester):** `prod-vpc` \| **Target VPC ID (Accepter):** Select your second test network (`corp-vpc`).<br>3. Click **Create** -> select the entry link from the listing dashboard -> click **Actions** -> select **Accept request** -> click **Accept**.<br>4. **Update Network Routing Tables:** Go to **Route tables** -> select `prod-private-rt` -> click **Edit routes** -> click **Add route**.<br>5. Enter corporate destination CIDR `172.16.0.0/16` -> under *Target*, select **Peering Connection**, click your peering link ID, and click **Save changes**. |
| **10. Virtual Private Gateway** | 1. In the VPC Console, click **Virtual private gateways** -> click **Create virtual private gateway**.<br>2. Set **Name tag:** `prod-vpn-gateway` \| leave ASN settings as *Amazon default ASN* -> click **Create virtual private gateway**.<br>3. Highlight the entry line in the dashboard list -> click the **Actions** dropdown menu -> select **Attach to VPC**.<br>4. Choose `prod-vpc` from the target dropdown menu space -> click **Attach to VPC**. |
| **11. Customer Gateway (CGW)** | 1. In the VPC Console, click **Customer gateways** -> click **Create customer gateway**.<br>2. Set **Name tag:** `on-prem-customer-gateway` \| Set **Routing:** `Static`.<br>3. **IP address:** Input the external public static IPv4 routing address block of your local infrastructure environment router (e.g., `1.2.3.4`) -> click **Create customer gateway**. |
